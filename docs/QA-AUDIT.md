## Coverage and documentation findings

- The baseline gate scanned 250 paths, called 194, and listed 42 reasons; 14 paths were unexplained. The live Express inventory found 274 distinct API method/path pairs, plus explicit `/home` and `/welcome` page routes. It does not count static-file middleware or implicit methods. The fixed API gate accounts for all 274. Calling a route only to verify rejection counts as a call; it is not a positive end-to-end test. [Full route inventory](QA-ROUTES.md).
- An existing double registration for `POST /api/commerce/compare` leaves the second handler unreachable with normal Express dispatch. The two handlers differ in provider fallback and response fields. **Medium, open:** choose the intended contract before deduplicating. Real prices and checkout totals are not verified.
- **Low, open:** Home Assistant's status endpoint reports `connected:false` immediately after a successful connection; the page uses `configured` and a separate entity fetch, so the tested UI still works. Decide whether status should report a last successful probe, a fresh probe, or configuration only before changing that response contract.
- The route exemptions are enumerated with reasons in `tests/api.test.js` under `NOT_TESTABLE`. Some have dedicated software suites (Hello, TTS or events); some deliberately stop short of physical effects, downloads or real network calls.
- 186 distinct rule intents have phrase coverage (395 checks including the coverage gate). The feature report lists 187 entries including negation. The browser sweep proves that a sample gets a reply; a reply alone cannot prove the requested effect or all possible utterances.
- The README’s old 95 suites, 180 intents, and 205 routes were stale. The file map left out the Today/integration scripts, Phone Hub/calling, Agent Platform, recovery/storage modules, package manifests and launch helpers. The audit corrected the headline counts and added the missing root runtime files; grouped paths such as `dashboard.js/.css` resolve to existing files, and the study guide/lesson are under `docs/`.
- Important undocumented runtime/config knobs: `OLLAMA_URL`, `JARVIS_MODEL`, `JARVIS_WHISPER_DIR`, and `NTFY_URL`. Other environment inputs such as `JARVIS_TEST`, `JARVIS_TEMP_DIR`, and weather/tender fixture URLs are developer hooks. The command-line instructions should use port 3002; do not use the test port override for a second live copy.
- A literal-call scan of 64 UI scripts found 407 calls with no unmatched route and recognized callers for 202 distinct routes. The other 72 cannot be called dead from that scan: helper-built paths, settings wrappers, dynamic URLs, API-only operations and server-side consumers may not appear. The static relative-import scan found no unresolved product import; its potential misses came from quoted fixture code in `nodecheck` and `projectwiki` tests.
- The Android source checks and some security/config suites are asserts against source or simulated behavior. Android, Twilio, a live model, and the physical safety controls need real operator runs. A complete button-by-button run and a complete API UI caller cross-reference remain **UNVERIFIED**.

## Manual verification checklist

Use your one JARVIS at `localhost:3002`. For irreversible actions, stop at the confirmation dialog and cancel.

- **Mic, wake, TTS:** In Settings use **Test my mic**; hold Space and say “what time is it?” in each selected language, including Telugu and Kannada. With a different app focused, say “Hey Jarvis, what time is it?” and confirm one reply. Switch to FRIDAY; test browser and neural voices; turn neural voice off and press Stop mid-reply. Test offline speech with an installed model, then check the missing-model message on an unconfigured profile.
- **Briefing:** Set a time a minute ahead with **Speak replies** off; confirm it does not run. Enable speech and schedule the next time; open two tabs and confirm one spoken reply. Restart within the window and check it does not repeat. Restart more than ten minutes late on another day and check it does not replay. Compare calendar/weather with Online tools on and off.
- **Windows Hello:** Enroll via **Settings → Data**, enable **Lock JARVIS**, lock now, and authenticate from localhost. Test a wrong/cancelled prompt, then the configured idle interval and a restart. Confirm reminders still fire in the background. No need to execute a power action.
- **Camera and laptop:** With a test document, scan and search the PDF for a visible word; scan a QR without opening it; cover or block the camera and check uncertain presence does not lock. With a spare app/window and disposable screenshot, test open/close, snap, screenshot/OCR and clipboard; close or restore settings afterward. Observe a charger unplug/replug without changing network settings. For reversible basic controls, run `npm run test:live` when ready.
- **Real calendar and Home Assistant:** Add a disposable private HTTPS calendar feed with one event today and an event beyond 14 days; verify Today/briefing, disconnect and confirm disappearance. Use a spare lamp or fan: cancel the first request, approve a second, observe the physical effect and receipt, then restore the original state. Confirm sensor controls are read-only; disconnect.
- **Twilio, Android, ntfy and Tailscale:** Follow `docs/CALLING.md`, `docs/PHONE-HUB.md`, and `android/phonehub/README.md`. Use your own test number, pair a physical phone via QR and a trusted gateway certificate, grant only voice first, and check call refusal; then explicitly grant calls and request one announcement. Test ntfy delivery, fresh/replayed Authenticator codes, background notification after Android sleeps, and Tailscale from the second device on the tailnet. Revoke the device and verify it loses access.
- **Model, dev tools and startup:** Try local-only Build/Plan/Ask in a disposable folder, including undo; separately verify each installed compiler and the intended editor hand-off. Test desktop Stop/Start, offline START button, sign-in autostart and live update check as operator actions. Check Phone Hub state-file permissions with Windows ACL tooling; POSIX mode checks on a POSIX host are separate.

## Top five remaining risks

1. Real hardware, phone pairings, TLS trust, Twilio and LAN/tailnet behavior remain unverified; simulated test inputs cannot establish those outcomes.
2. The live process was not restarted to load this working tree. The proof uses isolated copies matching the changed sources.
3. The duplicate commerce handler can conceal inconsistent fallback and result fields. No checkout-verified prices were demonstrated.
4. A passing route or command count can conceal untested positive paths, browser buttons, real providers, and file-symlink checks blocked by Windows privileges.
5. The full result depends on existing uncommitted integration work. Keep the local changes together and test the eventual committed release candidate before treating branch history as deployable.
